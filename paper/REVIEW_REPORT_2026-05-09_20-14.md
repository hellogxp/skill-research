## 一句话总结

本文提出SkillWeaver框架解决组合式技能路由问题，通过分解-检索-组合三阶段流程和Skill-Aware Decomposition (SAD)技术，使得7B模型+SAD超越72B vanilla模型（54.2% vs 36.8%），揭示了任务分解是组合式路由的关键瓶颈。

## 核心优势

1. **问题定义精准**: 首次形式化定义Compositional Skill Routing问题，明确了分解-检索-组合三阶段目标函数

2. **关键技术洞察**: "分解是瓶颈"的发现通过Oracle实验清晰验证（99.5% vs 33.9%），SAD设计直接针对该瓶颈

3. **跨模型泛化验证**: 在5个模型（7B-72B）上验证SAD有效性，7B+SAD超越72B vanilla是有说服力的结果

4. **诚实披露局限性**: Limitations章节明确承认模板高重叠问题、缺乏端到端评估、SAD双倍延迟等缺陷

5. **相关工作覆盖全面**: 涵盖MCP生态、SkillRouter、AnyTool、CRAFT等最新工作，对比公平

## 核心问题（按严重程度排序）

### P0 (必须解决)

**无P0级别问题**

### P1 (强烈建议解决)

1. **Human Hard Queries性能下降未充分解释**
   - 问题描述: Table 7中human hard queries从17.0%下降到9.4%，仅用"hint dilution"解释，缺乏机制分析
   - 建议: 补充消融实验，验证自适应H值是否能缓解该问题；或承认hard subset样本量(10条)统计效力不足

2. **14B模型异常需要更深入分析**
   - 问题描述: 14B模型低于7B是反直觉的，Appendix D的解释(prompt sensitivity)是后验假设，缺乏独立验证
   - 建议: 增加controlled experiment：固定prompt格式，测试不同temperature/grammar constraints对14B的影响

### P2 (建议解决)

1. **LLM-Direct baseline对比不完全对称**
   - 问题描述: LLM-Direct没有显式分解步骤，与主pipeline不完全是apple-to-apple对比
   - 建议: 增加"decompose-then-select"变体，让LLM先分解再从top-50中选择

2. **Text Overlap问题已承认但未量化其对SAD增益的影响**
   - 问题描述: ROUGE-L=0.845的重叠可能同时inflates vanilla和SAD结果
   - 建议: 分析SAD在低重叠子集上的增益是否仍然显著

3. **DAG Planner作为"optional extension"但未见与vanilla pipeline的直接对比**
   - 问题描述: Appendix E评估了DAG planner但未展示其对主结果的贡献
   - 建议: 明确DAG planner是否提升Chain Exact Match或Chain Category Match

## 与竞品/相关工作的对比分析

| 方法 | 核心区别 | 本文优势 |
|------|---------|---------|
| **SkillRouter** | 单技能路由，body主导 | 组合式路由，metadata匹配足以应对分解后的窄子任务描述 |
| **AnyTool** | 层级自反思导航API池 | 显式分解+检索，可并行执行（DAG） |
| **CRAFT** | 每query动态创建工具集 | 固定skill pool + 检索，不依赖工具生成 |
| **TaskBench** | 固定工具集的多步任务 | 大规模skill库(2595)+检索 |

**关键差异化声明**:
> "All these methods select tools independently per query; none jointly optimizes decomposition, retrieval, and inter-skill compatibility for compositional tasks."

该声明准确，与SkillRouter、AnyTool等的区别清晰。

## 审稿人可能的Questions for Authors

1. **Q1**: The 7B+SAD outperforming 72B vanilla is impressive. Does this hold across different random seeds? Have you tested with different decomposer temperatures?

2. **Q2**: The human hard query performance drop (17.0%→9.4%) is concerning. Could adaptive H selection (e.g., based on query complexity estimation) mitigate this?

3. **Q3**: The 14B anomaly suggests prompt sensitivity. Have you experimented with constrained decoding or grammar-based generation to improve JSON parse rates?

4. **Q4**: The DAG planner evaluation (20 queries) is small-scale. Can you provide more evidence that dependency detection is reliable enough for practical use?

5. **Q5**: How would SAD perform with closed-source models (GPT-4, Claude) that may have different instruction-following behaviors?

## 结论

这是一篇实验扎实、分析深入的工作。核心贡献是:
1. 形式化组合式技能路由问题
2. 识别分解瓶颈并设计SAD有效缓解
3. 构建首个组合式路由benchmark

主要风险是benchmark的高文本重叠和hard human queries的性能下降。但作者诚实披露这些局限性，并在human queries上验证了SAD的相对增益仍然显著。

**推荐决定**: Accept
