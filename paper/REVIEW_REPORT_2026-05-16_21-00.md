## 一句话总结

本文形式化定义了 Compositional Skill Routing 问题，提出 SkillWeaver 框架和 Skill-Aware Decomposition (SAD) 技术，通过检索增强的分解反馈环使 7B 模型超越 72B vanilla（CatR@1: 54.2% vs 36.8%），并在 200 条 human-style queries 上验证 SAD 的分解准确率提升达 91%（33.5%→64.0%）。

## 核心优势

1. **问题形式化精准**: 首次将 Compositional Skill Routing 定义为联合优化问题（Eq.1），清晰区分了与单技能路由的本质差异

2. **关键瓶颈识别 + 解决方案**: Oracle 实验（99.5% vs 33.9%）精确定位了分解瓶颈，SAD 直接针对该瓶颈设计，逻辑链条完整

3. **Human-style query 泛化显著增强**: 200 条 human-style queries 上 DA 提升 91%（33.5%→64.0%），hard queries 也受益（65%→80%），彻底回应了 text overlap 质疑。相比之前 55 条 pilot，这是质的飞跃

4. **跨模型泛化的强结果**: 7B+SAD > 72B vanilla 是 compelling 的 headline result，且在 5 个模型上一致验证

5. **SAD vs RAG 区分到位**: 新增的 "SAD beyond standard RAG" 段落清晰阐述了跨阶段反馈环的独特性，配合 category-only ablation（71% skill-level 贡献）提供了量化证据

6. **Adaptive Hints 实验补充完整**: 验证了 complexity-adaptive 策略的有效性（Chain EM: 0.397→0.483, +22%），为 hard queries 的 hint dilution 提供了具体解决方案

## 核心问题（按严重程度排序）

### P0 (必须解决 — 可能导致 reject)

**无**

### P1 (强烈建议解决 — 影响评分)

1. **Human-style queries 的 CatR@1 缺失**
   - **问题**: Table 5 (tab:human) 报告了 DA 和 CatR@10，但**没有报告 CatR@1**——这是论文的 primary metric。读者无法将 human-style queries 的结果与主表的 CatR@1=54.2% 直接对比。
   - **风险**: 审稿人会追问 "CatR@1 在 human queries 上是多少？"
   - **建议**: 在 Table 5 中增加 CatR@1 列，或在正文中报告该数字。

2. **200 条 human-style queries 的生成方法描述不够透明**
   - **问题**: 正文说 "200 human-style queries generated by an independent LLM (qwen-max) with instructions to avoid skill names"，但没有说明：
     - 生成 prompt 是什么？
     - 如何验证 queries 的质量和多样性？
     - 如何确保 ground truth skill 映射的正确性？
   - **风险**: 审稿人可能质疑 "LLM-generated ≠ human-written"，以及 ground truth 的可靠性
   - **建议**: 在 Appendix 中增加 human-style query 生成的 prompt 模板和质量验证步骤

3. **数据不一致：hard queries 数量**
   - **问题**: 
     - Limitations 说 "The hard subset (63 template, 40 human-style queries)"
     - Appendix hard-hints 说 "The 40 hard human-style queries require 4--5 skills"
     - 但 Table 5 (tab:human) 的 hard 行显示 n=40
     - 之前文档中提到的 55 条 human queries 的数据似乎已被替换，但 Appendix hard-hints 段落中仍引用 "10 hard human queries" 的 2.1/4.3 category coverage 数据
   - **风险**: 数字不一致是审稿人最容易发现的问题
   - **建议**: 统一检查所有引用 human query 数量的地方，确保一致为 200 条（80 easy + 80 medium + 40 hard）

### P2 (建议解决 — 锦上添花)

1. **Constrained Decoding 结果过于 preliminary**
   - 问题: Appendix constrained-decoding 只报告了 DA=0.72 和 parse rate=0.98，没有报告 CatR@1——这是最重要的下游指标
   - 建议: 补充 CatR@1 数据，否则难以评估 constrained decoding 的实际价值

2. **Adaptive Hints 表格指标体系与主表不同**
   - 问题: Table adaptive-hints 报告的 vanilla DA=0.000，与主表的 DA=0.360 矛盾；R@1=0.463 也与主表的 0.005 矛盾。看起来这个实验的评估设置可能不同
   - 建议: 在 caption 或正文中明确说明评估协议差异，或统一指标

3. **缺少 closed-source model 对比**
   - 问题: 只评估了开源模型，GPT-4/Claude 等可能 vanilla decomposition 就很强
   - 建议: Limitations 中已提及，可保持现状

4. **页数可能超限**
   - 问题: PDF 为 13 页，ARR 主文限制 8 页 + 不限 appendix。需确认主文部分不超过 8 页
   - 建议: 编译后检查 Conclusion 结束的页码

## 与竞品/相关工作的对比分析

| 方法 | 设定 | 核心差异 | 本文优势 |
|------|------|---------|---------|
| **SkillRouter** (2025) | 单技能路由 | Bi-encoder + reranker | 组合式路由，SAD 反馈环 |
| **AnyTool** (EMNLP 2024) | 层级 API 导航 | Self-reflective agent | 显式分解，可并行，更快 |
| **CRAFT** (ICLR 2025) | Per-query 工具集 | 动态创建 toolset | 固定 pool + 检索，更高效 |
| **ReAct** | Iterative selection | Think-act-observe | 更快（1.5×），更稳定（14B 不崩溃） |
| **MCP-Zero** (2025) | Agent 主动发现 | 98% token 降低 | 语义路由 vs. 系统级协议 |
| **ToolACE** (2025) | Tool-calling 数据集 | Fine-tuning focused | 无需 fine-tuning，zero-shot |

**关键差异化声明的有效性**:
> "None jointly optimizes decomposition, retrieval, and inter-skill compatibility for compositional tasks."

这个 claim 是准确的。新增的 "SAD beyond RAG" 段落有效预防了 "这只是 RAG 的应用" 的质疑。
