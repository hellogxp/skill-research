## 2. 一句话总结

本文形式化了 Compositional Skill Routing 问题，提出 SAD 迭代反馈机制在 2,209 个真实 MCP skills 上将分解准确率提升 32.7%（51.0%→67.7%, p<10⁻⁶），DA-conditioned 分析揭示了 decomposition granularity 作为 routing 质量的 gating factor。

## 5. 核心优势

1. **问题形式化首创性**: 首次将 Compositional Skill Routing 定义为联合优化问题 (Eq.1)，清晰区分于 single-skill selection (SkillRouter) 和 flat query-to-toolset (CRAFT)

2. **真实 skill pool 规模**: 2,209 个真实 MCP servers 从公开生态提取，非合成数据，远超 TaskBench (~50 tools) 和 API-Bank (~50 APIs)

3. **DA-conditioned 分析揭示级联结构**: 发现 correct DA → CatR@1 从 34% 跳到 41%，CatR@10 达 82%，精确定位了 decomposition granularity 作为 gating factor 的机制。这个分析比数字本身更有价值

4. **Statistical honesty**: 诚实报告 CatR@1 不显著 (p=0.17, CI: [-0.005, +0.062])，并合理解释为 "granularity corrector, not retrieval precision enhancer"，在 Section 7 专设段落讨论

5. **Convergence 理论+实验一致**: Pigeonhole argument 证明必然收敛，实验验证 Jaccard 单调递增 (0.32→0.47→0.52)，Round 1 即捕获主要 DA gain

## 6. 核心问题（按严重程度排序）

### P0: Human-Style Queries Annotation 根本性缺陷

**问题**: Table 8 (Appendix A) 报告 Vanilla DA=8.5%, SAD DA=21.5%。Easy subset DA=2.5% (Vanilla)。数字极低的根本原因不是 "open-ended step boundaries"（论文的解释），而是 **ground truth annotation 的结构性错误**:

- 每个 subtask 的 description 字段是整条 query 的完整拷贝，没有拆分为独立子任务描述
- Ground truth skill 分配与 query 语义不匹配（如 Postgres query 标注了 MySQL server, communication task 标注了 ProductHunt server）
- 模型合理地将 "Pull sales from Postgres and email summary to marketing" 分解为 5-8 步，而 ground truth 标注为 2 步

这导致评估框架本身失效 — 不是模型差，是 annotation 与自然语言查询的分解粒度根本不兼容。

**论文的解释** ("annotation strictness rather than system failure", line 698) 回避了核心问题。如果 DA 指标在该数据集上系统性失效，报告它本身就有误导性。

**主文 line 425** 写 "DA improves from 8.5% to 21.5% (+153% relative)"。Vanilla DA=8.5% 意味着系统在 human queries 上基本不工作 — 这个数字放在 Results section 削弱而非增强论文。

**严重程度**: Fatal flaw — 审稿人会认为 human query 评估不可信，连带质疑 benchmark 设计能力。

**建议**:
1. 重新生成 200 条 human queries，确保每个 subtask 有独立 description（不是全 query 拷贝）
2. 引入 **Category-Set F1** 指标（不依赖步骤数，评估 predicted category set 与 ground truth 的 overlap），对 human queries 更公平
3. 如果来不及重做数据，从主文移除 line 425 的引用，在 Appendix 中更诚实地讨论 annotation 局限性

### P0-b: DA±1 数字可能有误

**问题**: 根据 Table 8 的 per-difficulty 数据手算:
- SAD DA±1 = (0.400×80 + 0.625×80 + 0.475×40) / 200 = 101/200 = **0.505**
- 但论文写 **48.3%**

差值约 2 个百分点。可能是 weighted average 计算方式不同，也可能是数字错误。需要验证。

### P1: CatR@1 不显著 — 核心 Routing 指标无改善

**问题**: SAD 的核心卖点是改善 skill routing，但 CatR@1 (34.2%→37.0%, p=0.17) 不显著。论文的解释合理但不改变事实：

- 标题是 "Compositional Skill **Routing**"，但核心改善在 decomposition step counting
- DA=1 conditioned CatR@1=41% 意味着即使分解正确，仍有 59% 的步骤匹配不到正确 category
- 审稿人可能质疑：如果只修步骤数，简单的 prompt engineering ("output exactly N steps") 是否能替代 SAD？

**建议**:
- 增加 "constrained step count" ablation：给 vanilla decomposer 一个 "output exactly K steps" prompt，看 DA 是否能匹配 SAD（如果不能，证明 SAD 的 vocabulary alignment 有独立价值）
- 或在 Discussion 明确 reframe：SAD 解决的是 "decomposition-retrieval alignment"，非 routing precision

### P2: Baselines 设计不公平

**问题**:

1. **ReAct baseline (DA=0%)**: ReAct 是 iterative execution agent，不做 explicit upfront decomposition。用 DA (步骤数匹配) 评 ReAct 是 category error。ReAct 的正常输出不是一个步骤列表，而是 thought-action-observation 序列。
   - 论文已在 caption 说明了评估协议差异，但将 DA=0% 放在 Table 1 中与 SAD 并列仍然误导

2. **LLM-Direct baseline**: 用 qwen-max (强模型) 而非 7B (SAD 使用的模型)，且给 100 个 skill names。模型和 prompt 设置都不同，无法隔离 SAD 的贡献。

3. **缺少关键 baselines**:
   - "Vanilla 7B + cross-encoder reranking" — 隔离 retrieval 改进 vs decomposition 改进
   - "Vanilla 7B + step count constraint prompt" — 隔离 SAD 的 vocabulary alignment vs 纯粹步骤数修正
   - 与 CRAFT 在 compositional queries 上的对比（CRAFT 最 related）

**建议**: 
- ReAct: 改为评估其产出的 tool calls 是否覆盖 ground truth categories (tool-set recall)，而非 DA
- LLM-Direct: 用 7B 控制变量
- 补充 "step count constrained vanilla" baseline

### P3: Compose 阶段有方法描述但零评估

**问题**: 
- Section 3.3 定义了 compose 阶段：compatibility scoring (Eq.2), DAG planner, I/O type coercion
- Section 3.3 最后承认 "This paper focuses on the decompose-retrieve stages"
- 标题包含 "Compose"
- 除了 Appendix H 的 mock executor pilot (30 queries, mock success rates), compose 阶段无任何定量评估

审稿人会认为这是 incomplete contribution: 提出三阶段框架但只评估两个。

**建议**:
- 选项 A: 去掉 compose 的方法细节（Eq.2 简化为一句话 future work），标题改为不含 "Compose"
- 选项 B: 提供 with/without compatibility scoring 的 ablation (e.g., random selection from top-k vs scored selection)

### P4: Template Query Text Overlap 风险未量化

**问题**: 
- Query 由 "template verb phrases combined across categories" 生成 (Section 4.2)
- 论文声称 "descriptions do not directly copy skill names"，但未报告任何 overlap 指标
- CatR@10=69% 可能被 lexical matching 抬高 — bi-encoder (MiniLM) 对 short-text overlap 非常敏感
- Paraphrase test 仅 50 queries，且用 LLM paraphrase 仍保留语义近义词

**建议**:
- 报告 query→skill 的 BM25 recall@10 作为 lexical matching baseline
- 如果 BM25 R@10 接近 bi-encoder 的 69%，说明 semantic matching 被高估
- 扩大 paraphrase test 到全 300 queries

## 9. 审稿人可能的 Questions for Authors

**Q1** (针对 P1 — CatR@1 不显著):
> SAD 的 CatR@1 提升 (34.2%→37.0%) 不显著 (p=0.17)。如果 SAD 不改善实际 per-step routing precision，它的实际部署价值是什么？一个简单的 "output exactly N steps" prompt constraint 是否能达到类似的 DA 提升而无需两次 LLM inference？

**预判 Rebuttal**: 作者可能指向 DA-conditioned analysis (DA=1 时 CatR@1=41%) 证明 DA 提升间接带来 routing 改善。
**追问**: 请提供 "step-count-constrained vanilla" 的 DA 数字。如果 constraint prompt 的 DA ≈ SAD DA，则 SAD 的两次 inference 开销不合理。

**Q2** (针对 P0 — Human queries):
> Easy human queries 上 Vanilla DA=2.5%。表 8 的 ground truth step count 是 2，但 Qwen-7B 在 compositional easy queries (也是 2-step) 上 DA=44.7%。为什么同样 2-step 的 human query DA 下降了 18x？是否存在 annotation artifact？

**预判 Rebuttal**: 作者会指向 "open-ended step boundaries" 和 DA±1 metric。
**追问**: 请展示 3-5 个 human easy queries 的 model prediction vs ground truth 步骤，让审稿人判断 annotation 还是 model 的问题。

**Q3** (针对 P3 — Compose 阶段):
> Eq.2 定义了 compatibility scoring + DAG planner，但方法部分明确说 "This paper focuses on the decompose-retrieve stages"。请问 Compose 阶段在当前系统中是否实际运行？如果运行了，为什么不报告结果？如果没运行，为什么在方法中详细描述？

**预判 Rebuttal**: 作者会指向 pilot execution study (Appendix H) 和 "architectural completion" 的说法。
**追问**: Mock executor 的 80-95% success rate 是如何 "calibrated from published benchmarks" 的？请给出具体来源。

**Q4** (针对 P4 — Text overlap):
> CatR@10=69% 在 2,209 skills 上看起来不错，但没有 BM25 lexical baseline 对比。请问 BM25 在同样设置下的 R@10 是多少？如果 BM25 R@10 > 50%，说明 bi-encoder 的优势可能被高估。

**预判 Rebuttal**: 作者可能指向 paraphrase robustness (DA 仅降 4pp) 和 metadata-only encoding 作为间接证据。
**追问**: Paraphrase 仅测了 50 queries，且 LLM paraphrase 保留语义近义词。请在全 300 queries 上报告 BM25 R@10。

**Q5** (针对 ReAct baseline):
> ReAct DA=0% 是因为 ReAct 根本不做 upfront decomposition — 它 iteratively 执行 think-act-observe。将 ReAct 的最终 action 序列长度与 ground truth step count 比较是 category error。请解释为什么这是一个公平的对比。

**预判 Rebuttal**: 作者会说 ReAct "collapses multi-step tasks into single actions"，论证 explicit decomposition 的必要性。
**追问**: ReAct 的 action 序列确实覆盖了所有 ground truth categories 吗？请报告 ReAct 的 category coverage (而非 DA)。

## 结论

这是一篇 **分析深入、问题定义清晰** 的 empirical contribution 论文。DA-conditioned analysis 和 convergence 理论是真正的亮点。

但存在几个关键弱点需要修复：

1. **Human queries 数据** 是最大风险 — annotation 缺陷导致 DA=8.5% 这样的数字，放在论文里反而削弱可信度
2. **CatR@1 不显著** 限制了 "routing" 的贡献叙事 — 需要通过 ablation 证明 SAD 的 vocabulary alignment 有独立价值（超越简单的 step count constraint）
3. **Baseline 设计 + Compose 阶段评估缺失** 可能被审稿人抓住

**最关键的修复**: 修好 human queries 数据质量，让 DA 达到 30-60% 的合理范围。当前 8.5% 的数字只会引发质疑。

**总体评估**: Borderline — 修好 P0 后可达 Weak Accept；P0+P1 都修好可冲 Accept。
