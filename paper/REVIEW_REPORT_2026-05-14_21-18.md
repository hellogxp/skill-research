## 一句话总结

本文形式化定义了Compositional Skill Routing问题，提出SkillWeaver框架和Skill-Aware Decomposition (SAD)技术，通过检索增强的分解反馈环使7B模型超越72B vanilla（CatR@1: 54.2% vs 36.8%），并构建了首个组合式技能路由benchmark CompSkillBench。

## 核心问题（按严重程度排序）

### P0 (必须解决 — 可能导致reject)

**无**

### P1 (强烈建议解决 — 影响评分)

1. **技术新颖性偏incremental**
   - **问题**: SAD本质是"检索结果作为prompt hint"——这是RAG的标准模式。Bi-encoder retrieval + LLM decomposition也是现有组件的组合。审稿人可能认为novelty不足。
   - **风险**: EMNLP审稿人对"系统论文"的novelty要求较高
   - **建议**: 在Discussion中更明确强调SAD的独特性——它不是简单的RAG，而是一个**跨阶段反馈环**（retrieval → decomposition），且实验证明category-only hints只贡献29%的增益，说明需要skill-level semantics。可以增加一段"Why SAD is not just RAG"的讨论。

2. **Benchmark的text overlap问题仍是隐患**
   - **问题**: 尽管paraphrased benchmark验证了recall仅降2-3%，但核心问题是：oracle R@1=99.5%在真实场景中不可能达到。Human queries的CatR@1仅30.8%，与template的54.2%差距巨大。
   - **风险**: 审稿人可能质疑template结果的实际意义
   - **建议**: 在主文Results中更prominently报告human query结果（目前只在一个段落中提及），或将human queries作为primary evaluation、template作为controlled setting

3. **ReAct baseline数据存在疑点**
   - **问题**: 7B ReAct R@1=75.3%远高于7B+SAD的R@1=1.2%（同一个Table 2）。这两个数字的巨大差异需要解释——它们是否在评估同一件事？如果ReAct的R@1=75.3%是在oracle decomposition条件下，需要明确说明。
   - **风险**: 审稿人会直接质疑"为什么不用ReAct？"
   - **建议**: 明确ReAct的评估条件。如果ReAct确实在相同条件下R@1=75.3%，需要解释为何SAD pipeline的R@1如此低（可能是因为R@1要求exact skill match而CatR@1是category match）。建议在Table 2的caption或正文中增加一句解释。

### P2 (建议解决 — 锦上添花)

1. **缺少closed-source model对比**
   - 问题: 只评估了开源模型，GPT-4/Claude等可能vanilla decomposition就很强
   - 建议: 在Limitations中已提及，可保持现状

2. **DAG Planner贡献模糊**
   - 问题: Coherence=0.54意味着近半数dependency edges无效，且DAG不影响主指标
   - 建议: 当前"optional extension"定位合理，但可考虑在主文中降低DAG的prominence

3. **Human queries样本量不足**
   - 问题: 55条（hard仅10条），统计效力有限
   - 建议: 在camera-ready中扩展到100+条

4. **缺少MCP-Zero、ToolACE-MCP等2025-2026最新竞品的讨论**
   - 问题: Related Work中未提及这些最新工作
   - 建议: 在Related Work的MCP段落中增加1-2句

## 具体修改建议

### P1-1: 强化技术新颖性论述

在Discussion中增加一段：

```
\paragraph{SAD beyond standard RAG.}
While SAD superficially resembles retrieval-augmented generation, it differs in a fundamental way: 
standard RAG augments the \emph{generation} stage with retrieved context, whereas SAD augments 
the \emph{decomposition} stage---an upstream planning step that determines what to retrieve in 
the first place. This creates a cross-stage feedback loop (retrieval → decomposition → retrieval) 
that is absent in standard RAG pipelines. Our category-only ablation (Appendix B) confirms that 
SAD's benefit is not reducible to namespace narrowing: 71% of the gain requires skill-level 
semantic guidance, not just category information.
```

### P1-2: 提升Human Query结果的可见度

建议在Results主文中增加一个小表格或将human query结果提升到与template结果同等地位：

```
\paragraph{Generalization to natural queries.}
Table~\ref{tab:human} reports results on 55 human-written queries...
```

### P1-3: 澄清ReAct评估条件

在Table 2 caption或正文中增加：

```
ReAct results use a different evaluation protocol: the agent iteratively selects skills 
via a think-act-observe loop with access to the full skill library description; R@1 here 
measures whether the final selected skill matches ground truth (not retrieval recall). 
This is not directly comparable to the pipeline's retrieval-based R@1.
```

## 与竞品/相关工作的对比分析

| 方法 | 设定 | 核心差异 | 本文优势 |
|------|------|---------|---------|
| **SkillRouter** (2025) | 单技能路由 | Bi-encoder + reranker | 组合式路由，SAD反馈环 |
| **AnyTool** (EMNLP 2024) | 层级API导航 | Self-reflective agent | 显式分解，可并行 |
| **CRAFT** (ICLR 2025) | Per-query工具集 | 动态创建toolset | 固定pool+检索，更高效 |
| **ReAct** | Iterative selection | Think-act-observe | 更快（1.5x），更稳定（14B不崩溃） |
| **MCP-Zero** (2025) | Agent主动发现 | 98% token降低 | 语义路由 vs. 系统级协议 |

**关键差异化声明的有效性**:
> "None jointly optimizes decomposition, retrieval, and inter-skill compatibility for compositional tasks."

这个claim是准确的。但审稿人可能反驳：ReAct的iterative loop隐式地做了joint optimization。建议在Discussion中承认这一点并解释为何显式分解仍有优势（更快、更稳定、可解释）。

## 审稿人可能的Questions for Authors

1. **Q1 (Critical)**: Table 2中ReAct 7B的R@1=75.3%远高于SAD pipeline的R@1=1.2%。请解释这两个数字为何差异如此大，以及它们是否在评估同一件事。

2. **Q2 (Important)**: SAD本质上是将检索结果作为prompt hint——这与标准RAG有何本质区别？为什么不直接将其视为RAG的一个应用？

3. **Q3 (Important)**: Human queries的CatR@1仅30.8%（vs template 54.2%）。这是否意味着在真实场景中，系统的实际性能远低于论文主要报告的数字？

4. **Q4**: 72B+SAD的CatR@1(48.3%)低于7B+SAD(54.2%)。除了"hint anchoring"假设外，是否有更系统的解释？是否尝试过为72B调整H值？

5. **Q5**: Constrained decoding将14B parse rate提升到98%，但未报告对CatR@1的影响。这个关键下游指标是否也有改善？

6. **Q6**: 论文声称"metadata suffices for retrieval"，但这是在高text overlap条件下得出的结论。在paraphrased或human queries上，body-aware是否会反超metadata-only？

## 结论

这是一篇实验扎实、分析深入的empirical contribution论文，非常适合EMNLP的venue。核心贡献是：
1. 形式化Compositional Skill Routing问题
