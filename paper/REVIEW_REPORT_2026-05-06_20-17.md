## 一句话总结

本文首次形式化定义了 **Compositional Skill Routing** 问题（多技能组合路由），提出了三阶段框架 Decompose-Retrieve-Compose，并通过 Skill-Aware Decomposition (SAD) 显著提升了分解质量，使 7B 模型 + SAD 超越 72B 模型无 SAD 的表现。

## 核心问题（按严重程度排序）

### P0 - 必须修改

#### 1. Template-based Benchmark 存在 Data Leakage 问题

**问题描述**：
- Ground-truth sub-task descriptions 直接 derived from skill metadata
- Mean ROUGE-L = 0.845, BLEU-1 = 0.980, 37.8% exact copies
- 这导致 Oracle R@1 = 99.5% 可能是 inflated 的

**影响**：
- 审稿人可能质疑：这更像是一个 template matching 任务而非真正的 routing
- 绝对数值的可信度下降

**建议修改**：
1. 在 Section 6.2 "Text Overlap Disclosure" 之后，增加一个 **新的实验**：
   - 用 paraphrasing 模型重写 ground-truth sub-task descriptions
   - 报告 paraphrased 版本的 Oracle R@1
   - 预期：R@1 会下降（如 99.5% → 85-90%），但仍然验证 retriever 的有效性

2. 或者，在 Limitations 中更明确地承认：
   > "Our template-based benchmark primarily tests the upper bound of the retrieval pipeline under ideal decomposition. The human-written query evaluation (Section 7.4) provides a complementary lower-bound estimate."

#### 2. SAD 在 Hard Human Queries 上性能下降

**问题描述**：
- Template queries: SAD improves $\catrecall$@1 from 33.9% to 54.2%
- Human hard queries: SAD declines from 17.0% to 9.4%
- 论文给出的解释是 "hint dilution"，但不够深入

**影响**：
- 审稿人可能质疑：SAD 的泛化能力是否受限？

**建议修改**：
1. 增加 **adaptive hint selection** 的讨论：
   - Hard queries 涉及 4-5 个 skills
   - $H=15$ hints 可能包含大量 irrelevant skills
   - 建议：根据 query complexity 动态调整 $H$

2. 在 Future Work 中增加：
   > "Adaptive hint selection based on query complexity could mitigate the hint dilution issue observed in hard human queries."

#### 3. 缺少 End-to-End 执行评估

**问题描述**：
- 论文只评估了 retrieval quality ($\catrecall$@1)
- 没有验证：选出的 skills 是否能成功执行？
- DAG planner 的依赖检测准确率只有 53.7% coherence

**影响**：
- 审稿人可能质疑：高 $\catrecall$@1 是否意味着高 task success rate？

**建议修改**：
1. 在 Limitations 中明确承认：
   > "Our evaluation is retrieval-focused; full end-to-end evaluation with actual skill execution remains future work."

2. （可选）如果时间允许，增加一个 **small-scale pilot**：
   - 选取 20-30 个 queries
   - 用 LLM 模拟 skill execution
   - 报告 task completion rate

### P1 - 强烈建议修改

#### 4. 14B Anomaly 解释不够充分

**问题描述**：
- Qwen2.5-14B underperforms 7B: $\catrecall$@1 = 29.7% vs 33.9%
- Appendix 给出的解释：over-decomposition (avg 5.3 sub-tasks) + JSON parse failure
- 但为什么 14B 会产生这些问题？模型本身的问题还是 prompt 的问题？

**影响**：
- 审稿人可能质疑：SAD 是否真的 model-agnostic？

**建议修改**：
1. 增加一个 **diagnostic experiment**：
   - 用不同的 prompt templates 测试 14B
   - 报告不同 prompt 下的 decomposition behavior

2. 或者，在 Discussion 中更深入分析：
   > "We observe that larger models (14B, 72B) show different decomposition patterns. The 14B model tends to over-decompose, possibly due to its training data distribution. This suggests that model-specific prompt tuning may be necessary for optimal SAD performance."

#### 5. DAG Planner 贡献有限

**问题描述**：
- DAG planner 只在 Appendix 中有 pilot evaluation (20 queries)
- Coherence = 53.7%，Step Acc = 70%
- 对 main results 的贡献不明确

**影响**：
- 审稿人可能质疑：DAG planner 是否是核心贡献？

**建议修改**：
1. **方案 A**：将 DAG planner 降级为 "optional extension"
   - 在 Method 中标注为 "optional"
   - 在 Contributions 中移除或弱化

2. **方案 B**：增加 DAG planner 的评估
   - 扩展到 full benchmark
   - 报告对 final skill selection 的影响（$\catrecall$@1 有无 DAG planner 的对比）

#### 6. Related Work 缺少最新 MCP 生态工作

**问题描述**：
- MCP (Model Context Protocol) 是 2025-2026 年 agent 工具生态的重要发展
- 论文没有引用 MCP-related routing work (MCP-Zero, Adaptive Tool Routing, etc.)

**影响**：
- 审稿人可能认为文献不够全面

**建议修改**：
在 Related Work 中增加：
```
\paragraph{MCP Ecosystem and Tool Discovery.}
The Model Context Protocol (MCP) has become a standard for agent-tool integration, 
with over 10,000 public servers as of 2026. Recent work on progressive tool discovery 
[MCP-Zero, Adaptive Tool Routing] addresses the tool overload problem from a 
system perspective, while our work focuses on the compositional routing problem.
```

### P2 - 建议修改

#### 7. LLM-Direct Baseline 不够公平

**问题描述**：
- LLM-Direct 给模型 50 个 skill descriptions 让其选择
- 但没有给模型 query decomposition 的机会
- 可能低估了 LLM-Direct 的能力

**建议修改**：
在 Discussion 中承认：
> "Our LLM-Direct baseline does not perform explicit decomposition before selection. A fairer comparison would allow LLM-Direct to first decompose and then select, which we leave for future work."

#### 8. Metadata vs. Body 结论与 SkillRouter 矛盾

**问题描述**：
- SkillRouter (2025) 发现 body 是 decisive signal
- 本文发现 metadata-only 就足够
- 两者结论似乎矛盾

**建议修改**：
在 Discussion 中解释：
> "Our finding that metadata suffices for retrieval appears to contradict SkillRouter's conclusion that body is the decisive signal. We attribute this to: (1) compositional decomposition produces targeted queries that align naturally with concise metadata; (2) our skills have higher metadata quality due to curation. This suggests metadata quality, not modality, is the true bottleneck."

## 审稿人可能的 Questions for Authors

1. **关于 Benchmark Validity**
   > Your benchmark shows high text overlap (ROUGE-L=0.845) between ground-truth sub-tasks and skill descriptions. How would your method perform on more naturalistic queries where the sub-task descriptions don't match skill descriptions so closely?

2. **关于 Hard Query Performance**
   > SAD improves performance on easy/medium queries but degrades on hard human queries. What causes this, and how can it be addressed?

3. **关于 End-to-End Evaluation**
   > You evaluate retrieval quality but not execution success. If the selected skills are called, would they actually accomplish the task?

4. **关于 14B Anomaly**
   > Why does Qwen2.5-14B underperform the 7B variant? Is this a fundamental issue with the model or the prompt design?

5. **关于 DAG Planner**
   > The DAG planner shows only 53.7% functional coherence. Does it actually improve final skill selection quality?

6. **关于 Real-World Applicability**
   > How would your method handle skills with overlapping functionality or skills that require specific authentication/configuration?
