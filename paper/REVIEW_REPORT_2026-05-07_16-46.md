## 一句话总结

本文首次形式化定义了 **Compositional Skill Routing** 问题（多技能组合路由），提出了三阶段框架 Decompose-Retrieve-Compose，并通过 Skill-Aware Decomposition (SAD) 显著提升了分解质量，使 7B 模型 + SAD 超越 72B 模型无 SAD 的表现。

## 审稿人可能的 Questions for Authors（更新）

### 1. 关于 Benchmark Validity
> Your benchmark shows high text overlap (ROUGE-L=0.845). How would your method perform on more naturalistic queries?

**Response（已在论文中准备）：**
> "Importantly, the \emph{relative} gains from SAD are consistent across both settings: SAD improves $\catrecall$@1 by +20.8pp on template queries and +13.8pp on human queries, suggesting that the decomposition benefit is genuine rather than an artifact of text overlap."

### 2. 关于 Hard Query Performance
> SAD improves on easy/medium queries but degrades on hard human queries. What causes this?

**Response（已在论文中准备）：**
> "We attribute this to \emph{hint dilution}—hard queries require 4--5 skills spanning diverse categories, so the $H=15$ hint set inevitably includes many irrelevant skills... A promising mitigation is \emph{adaptive hint selection}."

### 3. 关于 End-to-End Evaluation
> You evaluate retrieval quality but not execution success. Would the selected skills actually work?

**Response（已在论文中准备）：**
> "Our evaluation is retrieval-focused; we do not measure whether correctly retrieved skills actually execute successfully in composition. A small-scale DAG planner pilot (20 queries) achieved Step Accuracy=0.70 and Coherence=0.54, indicating that execution-aware evaluation remains challenging."

### 4. 关于 14B Anomaly
> Why does Qwen2.5-14B underperform the 7B variant?

**Response（已在论文中准备）：**
> "We attribute this behavior to a \emph{prompt sensitivity} effect: the 14B model's instruction-following capacity sits in an intermediate regime where it recognizes the structured output format but lacks the precision to consistently produce well-formed decompositions."

### 5. 关于 Metadata vs. Body
> Your finding that metadata suffices appears to contradict SkillRouter. Why?

**Response（已在论文中准备）：**
> "We attribute the discrepancy to two factors: (1) compositional decomposition produces narrow, targeted sub-task descriptions... (2) our curated skill library has higher metadata quality... Together, these observations suggest that \emph{metadata quality}, not metadata modality, is the true bottleneck."

Concretely, for a hard query requiring skills from 4 distinct categories (e.g.,

too liberally, generating fine-grained sub-tasks (avg.\ 5.3) that include redundant steps...
Under SAD, the model over-corrects: rather than using hints as vocabulary guidance, 
it concatenates all skill names into a single JSON string...
