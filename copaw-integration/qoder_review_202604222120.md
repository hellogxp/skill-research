## Issue #1 — Class-level cache: thread safety + memory leak

**Severity**: 🔴 Critical  
**File**: `src/qwenpaw/agents/react_agent.py:468`

### Problem

```python
class QwenPawAgent(ToolGuardMixin, ReActAgent):
    # ...
    _skill_meta_cache: dict[str, tuple[float, dict[str, str]]] = {}
```

`_skill_meta_cache` is a **class attribute**, shared across ALL instances of `QwenPawAgent`. In a multi-request or multi-agent scenario:

1. **Thread Safety**: Multiple async coroutines concurrently reading/writing the same dict can cause race conditions
2. **Memory Leak**: The cache grows unbounded — entries are never evicted. Over time, especially with many different skills across sessions, this dict will consume increasing memory

### Impact

- In production with concurrent users, cached metadata from one user's session could be incorrectly served to another user
- Memory usage grows monotonically with the number of unique skill names encountered

### Suggested Fix

**Option A** (preferred — instance-level cache):
```python
def __init__(self, ...):
    self._skill_meta_cache: dict[str, tuple[float, dict[str, str]]] = {}
```

**Option B** (if sharing is intentional — add bounds):
```python
from collections import OrderedDict
import threading

class QwenPawAgent(ToolGuardMixin, ReActAgent):
    _skill_meta_lock = threading.Lock()
    _skill_meta_cache: OrderedDict = OrderedDict()
    _SKILL_META_CACHE_MAX_SIZE = 500

    @staticmethod
    def _read_skill_metas(skill_names, skills_dir):
        with QwenPawAgent._skill_meta_lock:
            # ... existing logic ...
            # Evict oldest entry if cache exceeds limit
            while len(QwenPawAgent._skill_meta_cache) > QwenPawAgent._SKILL_META_CACHE_MAX_SIZE:
                QwenPawAgent._skill_meta_cache.popitem(last=False)
```

## Issue #2 — Incomplete router cache config comparison

**Severity**: 🟡 Medium  
**File**: `src/qwenpaw/agents/react_agent.py:455-460`

### Problem

```python
def _get_or_create_router(self, sr_config: Any) -> Any:
    cached = getattr(self, "_skill_router", None)
    if cached is not None:
        cached_cfg = getattr(self, "_skill_router_config", None)
        if (
            cached_cfg is not None
            and cached_cfg.top_k == sr_config.top_k
            and cached_cfg.min_score == sr_config.min_score
            and cached_cfg.encoder == sr_config.encoder
        ):
            return cached
```

Only 3 of ~8 config fields are compared. `SemanticRoutingConfig` also includes:
- `max_tools`
- `token_budget`
- `mandatory_tools`
- `enabled`
- `persist_dir` (implicitly via constructor)

If any of these change, the cached router will be returned with stale configuration, causing incorrect routing behavior.

### Impact

- User changes `max_tools` from 20 to 5 in config, but the router still uses 20
- `mandatory_tools` changes are silently ignored

### Suggested Fix

```python
def _get_or_create_router(self, sr_config: Any) -> Any:
    from ..routing.router import SkillRouter

    persist_dir = Path(self._workspace_dir or WORKING_DIR) / ".semantic_index"
    cached = getattr(self, "_skill_router", None)
    if cached is not None:
        cached_cfg = getattr(self, "_skill_router_config", None)
        if cached_cfg is not None:
            # Compare full config snapshot
            if cached_cfg.model_dump() == sr_config.model_dump():
                return cached

    router = SkillRouter(config=sr_config, persist_dir=persist_dir)
    self._skill_router = router
    self._skill_router_config = sr_config
    return router
```

## Issue #4 — Redundant `load_config()` on every query

**Severity**: 🟢 Low  
**File**: `src/qwenpaw/agents/react_agent.py:388-390`

### Problem

```python
def _build_skill_hint(self, query: str) -> str:
    # ...
    from ..config.utils import load_config
    config = load_config()
    sr_config = getattr(config, "semantic_routing", None)
```

`load_config()` is called on **every single query** that triggers hint injection. Depending on implementation, this may involve file I/O and JSON parsing. The semantic routing configuration is typically static during runtime.

### Impact

- Unnecessary I/O overhead per query (likely milliseconds, but adds up under load)
- Not a correctness issue, but a performance optimization opportunity

### Suggested Fix

Cache the config at agent initialization time:

```python
def __init__(self, ...):
    # ... existing init ...
    from ..config.utils import load_config
    self._sr_config = None
    try:
        config = load_config()
        self._sr_config = getattr(config, "semantic_routing", None)
    except Exception:
        pass

def _build_skill_hint(self, query: str) -> str:
    sr_config = getattr(self, "_sr_config", None)
    if sr_config is None or not sr_config.enabled:
        return ""
    # ... rest of the method
```
