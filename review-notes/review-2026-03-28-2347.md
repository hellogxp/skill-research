## 一、相比旧版的显著改进

1. **SAD 是 solid 的方法贡献**: CatR@1 从 33.9% → 54.2% (+60%), DA 从 36% → 68.7%。H 参数的 inverted-U 消融有说服力，跨模型泛化（4个模型）也做了。
2. **DAG planner 从 placeholder 变成真正的方法**: 依赖检测（I/O overlap + producer-consumer + linguistic markers）、并行分组（Kahn's algorithm）、四维兼容性函数。
3. **Context window analysis 增加实用价值维度**: 99%+ token reduction 是好的 selling point。
4. **Related work 大幅扩充**: AnyTool, CRAFT, MetaTool, ToolSandbox, API-Bank, ToolQA, Decomposed Prompting, TPTU, AgentFlan 等。
5. **Limitations 和 Ethics Statement 符合 ARR 要求**。
6. **Figure 2 改用 `\includegraphics`**。

## 二、仍然存在的问题

### 问题 1: Figure 1 还是 `\fbox` 文本框

**严重程度**: 中
**位置**: Figure 1 (系统 overview)

Figure 1 仍然是 `\fbox{\parbox{...}}`。这是论文里最重要的图，审稿人第一眼就会看到。用文本框画的流程图在 EMNLP 投稿中观感很差。

**建议**: 用 TikZ 或 draw.io/Figma 导出 PDF。图的结构很简单（三个 stage + 箭头），画起来不费时间，但对 presentation quality 的提升巨大。

---

### 问题 2: 缺少强 decomposer baseline

**严重程度**: 高（最大的实验缺陷）
**位置**: Section 6 (Experimental Setup) + Section 7 (Results)

当前所有 decomposer 都是 7-14B 开源模型。审稿人会问:
- "用 GPT-4o 做 vanilla decomposition 会怎样？如果 GPT-4o vanilla > Qwen-7B+SAD，那 SAD 的价值在哪里？"
- "用 Qwen2.5-72B 做 vanilla decomposition 呢？你有 4×A100。"

不需要跑很多实验，只需要一个数据点来回答这个问题:
- 如果 7B+SAD 能打平或超过 72B vanilla → 论文最强的 selling point
- 如果 72B vanilla 远超 7B+SAD → 需要跑 72B+SAD 来证明 SAD 在强模型上也有效

**建议**:
- 加 Qwen2.5-72B-Instruct vanilla + SAD
- 或加 GPT-4o-mini 作为 decomposer（API 成本很低，300 queries 花不了多少钱）

### 问题 3: Benchmark query 生成过程不透明

**严重程度**: 高
**位置**: Section 5.2 (Query Generation)

论文说 "Compositional queries are generated by combining skills from different categories into multi-step tasks"，但没有说明:
- 是用 LLM 生成的还是模板拼接的？
- Ground truth sub-task descriptions 和 skill descriptions 的文本重叠度是多少？

这直接影响 oracle 99.5% 的可信度。如果 ground truth sub-tasks 就是 skill descriptions 的复制/轻微改写，那 oracle 的高性能是 trivially expected，不算发现。

**建议**:
- 在 Section 5.2 明确说明 query 生成方法（e.g., "We use GPT-4 to generate natural language queries given a set of skill categories and descriptions as input"）
- 报告 ground truth sub-tasks 和 skill descriptions 之间的 ROUGE-L 或 BLEU 分数
- 如果重叠度高，需要讨论这个 bias

---

### 问题 4: DAG planner 没有被定量评估

**严重程度**: 中高
**位置**: Section 4.3 + Section 7

花了很大篇幅描述 DAG planner（依赖检测、并行分组、四维兼容性），但实验中没有任何表格评估 planner 的效果。Limitations 里也承认 "the current benchmark evaluation uses sequential ground-truth chains"。

DAG planner 的所有技术细节（公式 4-6）在当前实验中都没有被验证。审稿人会问: "你写了这么多 planner 的内容，但实验里完全没有评估它，这算 contribution 吗？"

**建议（二选一）**:
- **路线 A**: 构建一小组有并行依赖的 queries（20-30 条），评估 DAG planner 的依赖检测准确率和并行分组质量
- **路线 B**: 大幅缩减 planner 的描述篇幅，诚实地说 "we implement a sequential planner with compatibility scoring; parallel planning is left to future work"，把省下的空间给更多 SAD 分析

### 问题 5: 14B 结果反常

**严重程度**: 中
**位置**: Table 7 (SAD cross-model)

Qwen2.5-14B vanilla (DA=28%, CatR@1=29.7%) 比 7B (DA=36%, CatR@1=33.9%) 差。论文解释为 "more verbose decompositions that deviate from the strict JSON format"。

这个解释不够有说服力。审稿人会怀疑是 prompt 或 chat template 的问题。

**建议**:
- 给出 14B 的具体失败例子（一个 verbose decomposition 的样本）
- 报告 14B 的 JSON parse success rate vs 7B
- 或者换成 Qwen2.5-32B / 72B 来替代 14B 的位置

---

### 问题 6: E2E pilot study 太小且指标定义不清

**严重程度**: 中低
**位置**: Discussion 段落

"functional coherence of 53.7%" — 这个指标是怎么定义的？论文里没有解释。20 条 query 的 pilot study 放在 Discussion 里可以，但如果审稿人追问，需要有清晰的回答。

**建议**: 要么在 appendix 里定义 functional coherence，要么删掉这个数字只保留 latency。

### 问题 7: Human-written queries 的细节不足

**严重程度**: 中
**位置**: Section 7.6 最后一段

35 条 human-written queries 是谁写的？写作指南是什么？和 template queries 的分布差异是什么？这些信息缺失会让审稿人质疑这个评估的可靠性。

**建议**:
- 说明 annotator 信息（几个人写的、背景）
- 说明写作指南（是否看到了 skill list）
- 扩大到 50+ 条
- 报告 human queries 的长度分布、难度分布

## 三、写作层面的问题

### 问题 8: Section 4 的结构

Stage 1-3 是 pipeline 的三个阶段，然后 Stage 4 (SAD) 是对 Stage 1 的改进。编号暗示 SAD 是 pipeline 的第四个阶段，但实际上它是 Stage 1 的增强版。

**建议改为**:
- Section 4.1: Task Decomposition (vanilla)
- Section 4.2: Skill Retrieval
- Section 4.3: DAG Planning
- Section 4.4: Skill-Aware Decomposition (改进 Stage 1)

或者把 SAD 放到 Results 之后作为独立的 "Improving Decomposition" section。

### 问题 9: Abstract 可以更紧凑

当前 abstract 有点长，包含了太多细节（"99% context reduction"）。

**建议聚焦三个核心 message**:
1. 问题定义（compositional skill routing）
2. 核心发现（decomposition is the bottleneck）
3. 解决方案（SAD, +60% improvement）
