本文形式化了 Compositional Skill Routing 问题，提出 SkillWeaver 框架（decompose-retrieve-compose）和 Skill-Aware Decomposition (SAD) 方法，在自建 benchmark 上证明 7B+SAD 超过 72B vanilla 和 72B LLM-Direct。

## 5. 核心优势

1. **"7B+SAD > 72B vanilla" 是一个非常强的 headline result**。证明了 retrieval-augmented decomposition 比单纯 scaling 更有效，这个发现对社区有指导意义。

2. **分析深度出色**。hint-induced consolidation（72B DA 下降的解释）、hint dilution（hard queries 下降的解释）、14B anomaly（JSON parse rate + over-decomposition）——每个反常结果都有深入分析，这在 EMNLP 投稿中是加分项。

3. **实验覆盖全面**。5 个模型 × 3 个 scale × vanilla/SAD × 3 个 baseline + 消融 + difficulty breakdown + human queries + constrained decomposition + context window analysis。

4. **Text Overlap Disclosure 体现了学术诚信**。主动报告 ROUGE-L=0.845 和 37.8% exact copies，并讨论了对 oracle 性能的影响。审稿人会欣赏这种透明度。

5. **LLM-Direct baseline 回答了关键问题**。"为什么不直接让 LLM 选？" 的答案是：7B+SAD (54.2%) > 72B LLM-Direct (47.0%)，structured decomposition 比 brute-force selection 更有效。

## 6. 核心问题（按严重程度排序）

### 问题 A（中高）：LLM-Direct baseline 没有出现在任何表格中

72B LLM-Direct=47.0% 和 7B LLM-Direct=39.6% 只在 Discussion 中用文字描述。这是一个重要的 baseline，应该出现在正式表格中。审稿人可能会质疑这个数据的可靠性。

### 问题 B（中）：Text Overlap Disclosure 中引用了 25.9%，但 SAD Results 写的是 30.8%

Section 5.2 (Text Overlap Disclosure) 写 "CatR@1: 25.9% vs 54.2%"，但 Section 7.6 (SAD Results) 写 human-written SAD CatR@1 = 30.8%。这两个数字不一致。25.9% 可能是 human-written + SAD 的旧数据，30.8% 是新数据。需要统一。

### 问题 C（中）：页数可能超限

721 行 LaTeX + TikZ 大图 + Algorithm box + 8 个表格 + 5 个 appendix sections。ARR 正文限制 8 页（不含 references 和 appendix）。需要编译确认。

### 问题 D（中低）：Compatibility weights (0.4, 0.2, 0.2, 0.2) 没有消融

四维兼容性函数的权重是手动设定的。审稿人可能会问为什么是这个比例。

### 问题 E（低）：Human-written queries 的 annotator 信息缺失

55 条 queries 是谁写的？几个人？有无写作指南？

### 问题 F（低）：公式 1 的 λ 参数没有在实验中出现

公式 1 定义了 rel + λ·compat 的联合优化目标，但实验中用的是 α 参数（公式 6）。λ 和 α 的关系没有说明。

## 8. 和竞品/相关工作的对比分析

### 和 SkillRouter (2025) 的关系
- SkillRouter 做 single-skill routing，本文做 compositional routing——问题不同
- SkillRouter 发现 body 是 decisive signal，本文发现 metadata 在 compositional setting 下足够——有趣的对比
- 建议在 Discussion 中更明确地解释为什么两个结论不矛盾

### 和 TaskBench (2023) 的关系
- TaskBench 用 fixed tool set，本文用 retrieval from large library——scale 不同
- 建议在 Related Work 中加一句定量对比（TaskBench 有多少 tools vs 本文 2595）

### 和 MCP-Zero (2025) 的关系
- MCP-Zero 做 active tool discovery（agent 主动请求 tools），本文做 compositional routing（预先规划 tool chain）
- 两者互补：MCP-Zero 解决 "何时需要 tool"，本文解决 "需要哪些 tools 的组合"
- 论文没有引用 MCP-Zero，建议加入 Related Work（如果 deadline 前发表了的话）

### 和 CRAFT (ICLR 2025) 的关系
- CRAFT 为每个 query 创建 specialized toolset，和本文的 compositional routing 有相似之处
- 区别：CRAFT 不做 decomposition，本文做 decompose-retrieve-compose
- 论文已引用 CRAFT，对比合理

## 9. 审稿人可能的 Questions for Authors

1. "Oracle decomposition 的 99.5% R@1 是否 trivially expected？你们自己报告了 ROUGE-L=0.845 和 37.8% exact copies。如果 ground truth sub-tasks 就是 skill descriptions 的复制，那 oracle 的高性能不算发现。"
   → 你已经在 Text Overlap Disclosure 中回答了这个问题，但可以更强调 human-written queries 的结果作为 complementary evidence。

2. "7B+SAD > 72B vanilla 是否因为 72B 的 prompt 没有优化？你们是否对 72B 做了 prompt engineering？"
   → 建议在 Appendix 加一句："All models use the same system prompt and chat template; no model-specific prompt engineering was applied."

3. "SAD 在 hard human queries 上性能下降 (17.0% → 9.4%)，这是否意味着 SAD 在实际使用中不可靠？"
   → 你已经解释了 hint dilution，但可以加一句 future work："Adaptive hint selection based on query complexity is a promising direction."

4. "DAG planner 的 20-query pilot 太小了。你们为什么不在全部 300 queries 上评估？"
   → 诚实回答：sequential ground truth 不支持 parallel evaluation。可以在 Limitations 中更明确地说。

5. "Compatibility weights (0.4, 0.2, 0.2, 0.2) 是怎么选的？"
   → 需要回答。

## 10. 总体判断

**推荐: Weak Accept (borderline)**

这篇论文有一个清晰的问题定义、一个有价值的方法贡献（SAD）、一个强有力的 headline result（7B+SAD > 72B vanilla/LLM-Direct）、和出色的分析深度。实验覆盖全面，text overlap disclosure 体现了学术诚信。

主要风险是：(1) pipeline 除 SAD 外的技术新颖性有限，(2) benchmark 的 template-based 构造和高 text overlap 削弱了绝对数字的说服力，(3) 页数可能超限。

如果能在投稿前完成 P0 的三项修改（页数、数据一致性、LLM-Direct 入表），我认为有 65-72% 的概率被接受。
