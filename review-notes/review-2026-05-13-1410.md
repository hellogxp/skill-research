## 5. 核心优势（5 条）

1. **问题定义具有前瞻性**: "Compositional Skill Routing" 是 2025-2026 年 MCP/Skills 生态的真实痛点，定义清晰且实用
2. **Benchmark 贡献扎实**: 2,595 skills × 300 queries × 17 categories × 3 difficulty levels 是该领域首个专用 benchmark
3. **SAD 方法简洁有效**: 不需要修改模型，跨 5 个模型（7B-72B）一致提升 +27%~+60%，7B+SAD 超越 72B vanilla 是 striking finding
4. **诚实披露 benchmark 局限**: 主动报告 ROUGE-L=0.845 text overlap，增加 paraphrased + 55 human queries 补充实验，学术诚信高
5. **分析深度**: 14B anomaly 机制分析、hint dilution 分析、50 failure cases 分类有洞察

## 6. 核心问题（按严重程度排序）

### P0（严重，影响接受）

**P0-1: 数据不一致 — Hardware 描述过时（A100 vs V100）**
- Line 353-355 声明使用 A100-80GB × 4
- 但 Appendix Table 11 (Latency Breakdown, L853) 新数据标注 "49 queries, **V100**"
- Limitations L582 也写 "on V100 for 7B"
- **严重矛盾**：审稿人会立即发现并对可复现性产生质疑

**P0-2: ReAct (14B) 结果异常但未解释清楚**
- Table 1 中 ReAct 14B R@1=15.7%，但 7B ReAct=75.3%
- Discussion L542 归因于 "JSON parsing failures" 但未给具体数字
- 审稿人会质疑是否是实现 bug

### P1（重要，需修改）

**P1-1: Latency 表 V100 数据与正文 claim 不一致**
- Discussion L549: "FAISS retrieval: median 568ms"
- 但 Table 11 显示 Retrieval ~10ms（差 50 倍）
- 568ms 是 DAG planner latency（见 Table 8, L760-768），**引用错误**

**P1-2: SAD 对 72B 的 "hint-induced consolidation" 讨论矛盾**
- L485-487: 72B vanilla DA=62.7% → SAD DA=50.3%（DA 下降）但 CatR@1 提升
- L476-477 Table 6 中 72B vanilla CatR@1=0.368 → SAD=0.483
- 与 "7B+SAD (54.2%) surpasses 72B vanilla" 形成对比，但此处 "72B+SAD (48.3%) < 7B+SAD (54.2%)" 这一意外结论未明确讨论

**P1-3: Related Work 严重遗漏 2024-2025 最新工作**
- 缺失: AnyTool (EMNLP 2024), CRAFT (ICLR 2025), MCP-Zero, Apigene Gateway, Adaptive Tool Routing (ATR), ToolACE-MCP
- 这些都是直接竞品，尤其 MCP-Zero 和 CRAFT 与本文思路非常接近
- 审稿人极可能因此降分或质疑 novelty

**P1-4: Context Window 表声称不合理**
- Table 7 L512: "SkillWeaver (avg.) 2.9 tools, ~1,160 tokens"
- 但 avg decomposition 有 2.9-5 sub-tasks，每 sub-task retrieve top-10，即使只保留 top-1 也有 2.9 skills
- 若计算包含 SAD hints（H=15），token 数远不止 1,160
- 需要澄清 "after SAD" 还是 "final selected skills"

## 9. 审稿人可能的 Questions for Authors

1. **[硬件]** 为什么 Hardware 写 A100 但 Latency 表是 V100？哪个是真实实验硬件？所有主表数据是同一硬件跑的吗？
2. **[ReAct]** ReAct 14B 如此低（15.7%）的具体原因？是实现问题还是模型能力问题？7B/72B ReAct 为何未测？
3. **[72B+SAD]** 为什么 72B+SAD (48.3%) 低于 7B+SAD (54.2%)？是否说明 SAD 不是 general solution？大模型使用 SAD 的正确方式是什么？
4. **[Text Overlap]** ROUGE-L=0.845 表明 benchmark 高度模板化。55 human queries 在 hard 子集 (n=10) 的 SAD decline (17% → 9.4%) 是否真正说明 SAD 在实际场景失效？
5. **[DAG Planner]** 20-query pilot 的 Coherence=0.54 表示一半 edges 不正确，为何将此作为 core contribution 放入 Section 3.3？
6. **[Context Tokens]** Table 7 的 1,160 tokens 是否包含 SAD 的 H=15 hints（每个 skill ~400 tokens = 6000 tokens）？
7. **[MCP-Zero]** MCP-Zero (2025) 声称 98% token reduction，与本文 99% 几乎相同，为何未直接对比？
8. **[Benchmark release]** 300 queries + 55 human queries 数据将如何发布？是否 anonymized？
