## 6. 核心优势

1. "7B+SAD > 72B vanilla" 和 "7B+SAD > 72B LLM-Direct" 双重 headline result，证明 structured decomposition + retrieval feedback 比 scaling 和 brute-force selection 都更有效。

2. 分析深度在 EMNLP 投稿中属于上乘：hint-induced consolidation（72B DA 下降的机制解释 + ROUGE-L 证据）、hint dilution（hard queries 下降的原因）、14B anomaly（JSON parse rate 71.3% vs 89.3%）。

3. 实验设计全面：5 模型 × 4 baseline × SAD 消融 × constrained decomposition × difficulty × human queries × 标准差。LLM-Direct baseline 现在有正式表格。

4. 学术诚信：text overlap disclosure (ROUGE-L=0.845)、承诺开源、SAD prompt 模板公开。

5. 论文叙事完整：发现问题（decomposition bottleneck）→ 提出方案（SAD）→ 验证方案（cross-model + human queries）→ 对比替代方案（LLM-Direct）→ 分析失败模式。

## 9. 审稿人可能的 Questions for Authors

Q1: "Table 2 (主表) 没有 SAD 结果，审稿人需要翻到 Table 6-7 才能看到最强结果。为什么不把 best result 放在主表？"
→ 建议在 Table 2 加一行 7B+SAD，或在 caption 中交叉引用。

Q2: "SAD 需要两次 LLM 调用，latency 是否翻倍？在实际部署中是否可接受？"
→ 建议在 Discussion 加一句："SAD adds one additional LLM call (~0.8s on A100), increasing end-to-end latency from ~0.6s to ~1.4s per query, which remains practical for interactive use."

Q3: "72B+SAD 的 DA 从 62.7% 降到 50.3%，但 CatR@1 从 36.8% 升到 48.3%。这是否说明 DA 这个指标本身有问题？"
→ 你已经用 hint-induced consolidation 解释了。可以进一步说："DA measures structural alignment (step count), while CatR@1 measures semantic alignment (skill relevance). SAD optimizes for the latter at the expense of the former, which is the correct trade-off for routing quality."

Q4: "55 条 human queries 中只有 10 条 hard。这个样本量是否太小？"
→ 诚实回答：是的，hard 的样本量有限。可以在 Limitations 中加一句。

Q5: "你们的 benchmark 中 37.8% 的 ground truth sub-tasks 是 skill descriptions 的 exact copies。这是否意味着 oracle 的 99.5% 是 trivially expected？"
→ 你已经在 Text Overlap Disclosure 中回答了。关键论点是：(1) oracle 的高性能证明 retriever 本身没问题，(2) LLM decomposition 的低性能证明 decomposition 是瓶颈，(3) human queries 提供了 complementary evidence。
