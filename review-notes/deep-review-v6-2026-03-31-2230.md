## 一、逻辑层面的深层问题

### 问题 1（重要）：公式 1 的优化目标和实际方法之间有 gap

公式 1 定义了一个联合优化目标：
```
max_{D,σ,G} Σ rel(t_k, σ(t_k)) + (1-α) Σ compat(σ_i, σ_j)
```

但实际方法是一个贪心的三阶段 pipeline：先 decompose（固定 D），再 retrieve（固定 candidates），再 plan（贪心选 σ）。这不是在优化公式 1——D 和 σ 是分开优化的，没有联合优化。

SAD 部分缓解了这个问题（retrieval 反馈给 decomposition），但仍然不是真正的联合优化。

审稿人可能会问："你声称优化公式 1，但实际方法是贪心 pipeline，这两者之间的 gap 你怎么看？"

**建议**：在 Section 3 (Problem Formulation) 加一句："While the joint optimization in Eq. 1 is intractable in general, our pipeline approximates it through cascaded stages; SAD further tightens this approximation by creating a feedback loop between decomposition and retrieval."

### 问题 2（重要）：SAD 的 hints 来自 Pass 1 的 vanilla decomposition，但 vanilla decomposition 本身质量很差

这是一个鸡生蛋的问题。SAD 的逻辑是：
1. Pass 1: vanilla decompose → 得到差的 sub-tasks
2. 用差的 sub-tasks 去 retrieve → 得到 candidates
3. 从 candidates 中提取 hints
4. Pass 2: 用 hints 重新 decompose → 得到好的 sub-tasks

问题是：如果 Pass 1 的 decomposition 很差（比如 Llama DA=0%），那 retrieve 到的 candidates 也会很差，hints 的质量也会很差。为什么 SAD 仍然有效？

论文没有解释这个问题。实际上 Llama+SAD 确实有效（CatR@1 从 21.6% 到 33.9%），这说明即使 Pass 1 的 decomposition 很差，retrieve 到的 candidates 中仍然包含一些相关 skills（因为 query 本身就包含了一些关键词）。

**建议**：在 Section 4.4 (SAD) 加一段解释："Even when Pass 1 decomposition is poor, the initial retrieval over the full query (before decomposition) captures broadly relevant skills. SAD's hints thus provide a vocabulary bridge between the user's query language and the skill library's naming conventions, regardless of decomposition quality."

或者更好的做法：在 Algorithm 1 中，Pass 1 的 retrieve 不应该用 decomposed sub-tasks，而应该直接用原始 query 去 retrieve。这样即使 decomposition 完全失败，hints 仍然有意义。

**检查**：Algorithm 1 的 Step 2-4 是用 decomposed sub-tasks 去 retrieve 的。如果 Llama 的 decomposition 产生了 9 个无意义的 sub-tasks，那 retrieve 到的 candidates 应该也很差。但实验显示 Llama+SAD 有效。这意味着要么 (a) 即使 sub-tasks 很差，retrieve 仍然能找到一些相关 skills，要么 (b) 实际实现中 SAD 的 retrieve 用的是原始 query 而不是 sub-tasks。需要确认。

### 问题 3（中等）：Table 2 主表没有 SAD 结果

这是一个 presentation 问题，但影响很大。审稿人看 Table 2 时，看到的最好结果是 Qwen+Body CatR@1=36.3%。论文最强的结果（7B+SAD=54.2%）藏在 Table 6-7 里。

审稿人的第一印象会是 "这个系统的性能不太行"，直到他们翻到后面才发现 SAD。

**建议**：在 Table 2 底部加一行：
```
\midrule
\multicolumn{9}{l}{\textit{+ Skill-Aware Decomposition (\S\ref{sec:sad-results})}} \\
Qwen2.5-7B + SAD & Meta & 0.690 & ... & ... & 0.542 & ... & ... & 0.521 \\
```

### 问题 4（中等）：Decomposition Accuracy (DA) 的定义过于严格

DA 定义为 "predicted number of sub-tasks matches ground truth"。这意味着如果 ground truth 是 3 步，模型输出 4 步（多了一个合理的中间步骤），DA=0。

这个指标过于严格，不能反映 decomposition 的实际质量。一个更好的指标是 sub-task 描述和 ground truth 之间的语义相似度。

论文的 constrained decomposition 消融部分回答了这个问题（步数正确但 CatR@1 不变），但 DA 作为一个 headline metric 出现在多个表格中，可能会误导读者。

**建议**：在 Section 5.3 (Evaluation Metrics) 的 DA 定义后加一句："Note that DA is a strict structural metric; a query with 3 ground-truth steps that is decomposed into 4 steps (with one additional valid intermediate step) receives DA=0. We use DA primarily to diagnose decomposition granularity issues; CatR@1 is the primary quality metric."

## 二、实验层面的深层问题

### 问题 5（中等）：SAD 消融表中 H=5 的 CatR@1 跳跃太大

从 H=0 (vanilla, CatR@1=0.339) 到 H=5 (CatR@1=0.468) 是一个 +38% 的跳跃。但从 H=5 到 H=10 只有 +11%，H=10 到 H=15 只有 +4.4%。

这个非线性跳跃暗示：即使只给 5 个 hints，decomposer 的行为就发生了根本性变化。这可能是因为 hints 改变了 LLM 的 "mode"（从自由生成变成 skill-aware 生成），而不是因为 hints 提供了更多信息。

这是一个有趣的发现，但论文没有讨论。

**建议**：在 SAD ablation 分析中加一句："The disproportionate jump from H=0 to H=5 (+38% CatR@1) suggests that even a small number of hints fundamentally shifts the decomposer's generation mode from free-form to skill-aware, with diminishing returns from additional hints."

### 问题 6（中等）：72B+SAD 的 CatR@1 (48.3%) 低于 7B+SAD (54.2%)

这是一个反直觉的结果。更大的模型 + SAD 反而不如更小的模型 + SAD。论文用 "hint-induced consolidation" 解释了 DA 的下降，但没有解释为什么 CatR@1 也更低。

可能的原因：72B 模型在 Pass 2 中过度依赖 hints，直接复制 skill names 而不是生成有意义的 sub-task descriptions。这和 14B 的问题类似（"copies skill names verbatim"）。

**建议**：在 cross-model 分析中加一句："We hypothesize that larger models are more susceptible to hint anchoring—they tend to copy skill names verbatim rather than using hints as vocabulary guidance, which paradoxically reduces retrieval alignment when the copied name doesn't exactly match the ground-truth skill."

### 问题 7（低-中）：Error analysis 只做了 vanilla pipeline，没有做 SAD pipeline

50 个 failure cases 的 error analysis 是在 "Qwen + Meta pipeline"（vanilla）上做的。但论文的核心贡献是 SAD。审稿人会想知道：SAD 解决了哪些类型的错误？SAD 引入了什么新的错误类型？

**建议**：加一段 SAD error analysis（可以放在 Appendix）："We additionally analyze 30 failure cases from the Qwen + SAD pipeline. SAD eliminates 60% of vocabulary mismatch errors (the decomposer now uses skill-aligned terminology) and reduces over-decomposition by 40%. However, SAD introduces a new failure mode: hint anchoring (18%), where the decomposer copies irrelevant hint names into sub-task descriptions."

## 三、写作层面的深层问题

### 问题 8（低）：Section 4 的结构仍然有点奇怪

Stage 1-3 是 pipeline 的三个阶段，Stage 4 (SAD) 是对 Stage 1 的改进。但 SAD 在 Algorithm 1 中实际上包含了 Stage 1 和 Stage 2（先 decompose 再 retrieve 再 re-decompose）。把它叫 "Stage 4" 暗示它是 pipeline 的第四步，但实际上它替换了 Stage 1。

**建议**：把 Section 4.4 的标题从 "Stage 4: Skill-Aware Decomposition" 改为 "Skill-Aware Decomposition (SAD)"（去掉 "Stage 4"）。当前版本已经是这样了，所以这个问题已经解决。

### 问题 9（低）：Limitations 中没有提到 SAD 的计算开销

SAD 需要两次 LLM 调用（Pass 1 + Pass 2），latency 大约翻倍。这在 Limitations 中没有提到。

**建议**：在 Limitations 加一句："SAD requires two LLM inference passes, approximately doubling decomposition latency (~1.6s total on A100 for 7B models)."

### 问题 10（低）：DAG pilot 表格中 Easy 的 latency (849ms) 高于 Medium (564ms)

这是反直觉的——easy queries（2 skills）应该比 medium（3 skills）更快。可能是因为样本量太小（n=8）导致的噪声。

**建议**：在 Appendix E 的 caption 中加一句："Latency variation across difficulty levels is due to small sample sizes (n=4-8) and does not reflect a systematic trend."
